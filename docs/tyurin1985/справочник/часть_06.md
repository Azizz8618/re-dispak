## 1. 6.1. Основные понятия

### 1.1. Процесс, состояние и блокировка

| Понятие | Определение книги | Цитата |
|---|---|---|
| Последовательный процесс | работа, выполняемая последовательным процессором над программой с её данными | `tyurin1985-full.txt:10274-10275` |
| Асинхронный последовательный процесс | последовательный вид процесса; логически каждый процесс имеет свой процессор и программу, но два и более процессов могут разделять одну и ту же программу и процессор | `tyurin1985-full.txt:10276-10279` |
| Вектор состояния `e_i` | множество векторов `e¹, e², ..., eⁱ`; любой элемент определяет координатное положение процесса и значения всех используемых им данных; `e_i` есть полный описатель для процессора | `tyurin1985-full.txt:10281-10286` |

| Блокировка | процесс П находится в блокировке до получения сигнала, сообщения или ресурса от другого процесса | `tyurin1985-full.txt:10290-10293` |
| Продолжающийся | выполняется процессором или мог бы выполняться при доступности процессора данному процессу | `tyurin1985-full.txt:10294-10297` |

Мультипрограммная ОС описывается в терминах асинхронных последовательных процессов, которые действуют независимо, вступают в связь пересылкой обусловленных сообщений и иерархически разделяют общие ресурсы (`tyurin1985-full.txt:10299-10304`). Разделение ОС на процессы возможно лишь при аппаратной поддержке вычислительной системы; концепция процесса эффективно выделяет базовые задачи и упрощает изучение динамики (`tyurin1985-full.txt:10306-10314`).

### 1.2. Разделяемые данные и критический интервал

Книга рассматривает два процесса `P₁`, `P₂`, обновляющие запись `W` на отрезке `[T₀, T_r]`. `P₁` считывает `W` в момент `t₀ > T₀`, `P₂` в момент `t₁ > t₀`; операция изменения обозначена `D_i(W)`, `i = 1, 2`; время модификации `t`. Результат: в момент `t₀ + t` запись равна `D₁(W)`, в момент `t₁` она модифицируется снова и принимает значение `D₂(W)`, то есть работа `P₁` безвозвратно теряется (`tyurin1985-full.txt:10317-10343`).

**Критический интервал:** все другие процессы, пытающиеся проникнуть в занятый критический интервал, блокируются до его освобождения (`tyurin1985-full.txt:10345-10350`).

### 1.3. Взаимная блокировка и критерии взаимного исключения

Взаимная блокировка: ситуация, когда ни один процесс не может быть продолжен по вине другого (`tyurin1985-full.txt:10352-10355`). Примеры: одновременное использование ресурса несколькими процессами в мультипрограммном режиме (`tyurin1985-full.txt:10355-10358`); останов или зацикливание процесса внутри критического интервала, из-за чего ожидающие входы блокируются на неопределённое время (`tyurin1985-full.txt:10360-10364`). Постоянная проверка возможности входа блокированным процессом отнимает время центрального процессора и замедляет систему (`tyurin1985-full.txt:10366-10372`).

Критерии взаимного исключения (`tyurin1985-full.txt:10374-10385`):

1. ресурс используется в данный момент только одним процессом;
2. при потребности ресурс предоставляется за конечное время;
3. после получения ресурс освобождается за конечное время;
4. процесс не занимает процессор в состоянии блокировки по отсутствию ресурса;
5. алгоритм выбора процесса для входа в освободившийся критический интервал беспристрастен, иначе некоторый процесс может никогда не войти в интервал.

Общий алгоритм устраняет два типа тупиков (`tyurin1985-full.txt:10387-10395`):

* процесс вне критического интервала не может блокировать процесс внутри него;
* процессы, готовые к входу, не могут сколь угодно долго откладывать решение, кто войдёт первым.

### 1.4. Алгоритм на характеристиках `X_k` и `Y`

| Элемент | Значение и смысл | Цитата |
|---|---|---|
| `X_k ∈ B = {0, 1}` | характеристика процесса `k`; `X_k = 0` при попытке входа или работе внутри критического интервала; `X_k = 1` вне интервала; на входе в систему `X_k = 1` для всех `k = 0, 1, ..., n` | `tyurin1985-full.txt:10397-10413`, `tyurin1985-full.txt:10435-10438` |
| `Y` | общая характеристика, номер следующего процесса, который должен войти в интервал; на входе `Y = 0` | `tyurin1985-full.txt:10441-10445` |
| Проверка входа | процесс `j` устанавливает `X_j = 0`, проверяет `X_i` для `i = 1, ..., n, i ≠ j`; если все `X_i = 1`, вход безоговорочен | `tyurin1985-full.txt:10447-10458` |
| Ожидание | если не все `X_i = 1`, процесс проверяет `Y`; при совпадении `Y` со своим номером проверка права входа повторяется | `tyurin1985-full.txt:10460-10467` |
| Второй уровень самоблокировки | во избежание блокировки других процессов процесс присваивает своей характеристике единицу и ждёт очереди по `Y` | `tyurin1985-full.txt:10469-10474` |
| Формирование `Y` | внутри критического интервала к `Y` прибавляется 1 по модулю `n`; после выхода процесс формирует `Y` и переводит `X_k` в 1 | `tyurin1985-full.txt:10474-10482` |
| Свойства | `X_k` гарантируют исключение взаимного выполнения, `Y` гарантирует отсутствие взаимной блокировки, так как `Y` не меняется на участке принятия решения о входе | `tyurin1985-full.txt:10484-10493` |

Недостаток алгоритма: сложность и необходимость постоянного опроса характеристик (`tyurin1985-full.txt:10495-10499`).

### 1.5. Семафорные примитивы

| Примитив | Определение | Цитата |
|---|---|---|
| `V(S)` | неделимое увеличение неотрицательной целой переменной `S` (семафора) на 1 | `tyurin1985-full.txt:10501-10505` |
| `P(S)` | неделимое уменьшение `S` на 1, когда это возможно; при `S = 0` процесс переходит в состояние ожидания возможности операции | `tyurin1985-full.txt:10506-10511` |
| Доступ к `S` | при `V` переменная недоступна другим процессам; при `P` недоступна только когда уменьшение выполнимо; при одновременных запросах порядок доступа произволен | `tyurin1985-full.txt:10511-10519` |
| Действие | `V` переводит процессы из блокированного состояния в активное, `P` переводит в состояние ожидания | `tyurin1985-full.txt:10519-10521` |
| Реализация в ДИСПАК | на аппаратных возможностях БЭСМ-6 по закрытию всех процессов, кроме развивающегося; основное средство синхронизации процессов ОС; **все семафоры двоичные**, `B = {0, 1}` | `tyurin1985-full.txt:10523-10531` |

### 1.6. Приоритеты, тупики, классы ресурсов

Каждому процессу сопоставляется приоритет; возникает иерархия, где прерванный процесс продолжается после окончания более приоритетного (`tyurin1985-full.txt:10533-10539`). Пример безусловно быстрого процесса: подача сигналов реального времени, когда процесс готов к получению процессора (`tyurin1985-full.txt:10539-10543`).

Системный тупик: блокировка процессов запросами на ресурс, которые никогда не могут быть удовлетворены; безопасное состояние никогда не может привести к тупику; решением является стратегия распределения, при которой все состояния безопасны (`tyurin1985-full.txt:10545-10553`). Простая стратегия однократного запроса всех ресурсов сразу имеет недостаток: ресурсы заказываются по максимуму задолго до использования, удерживаются и вызывают простои (`tyurin1985-full.txt:10555-10567`).

Гибкая стратегия: иерархические классы `L₁, ..., L_max`. Утверждение книги: процессу разрешается использовать ресурсы любого класса `k`, если ему не распределены ресурсы классов `L_{k+1}, ..., L_max` (`tyurin1985-full.txt:10569-10577`). Запрос ресурса наивысшего класса `L_max` всегда удовлетворяется, так как процесс, получивший такой ресурс, не может захватывать дальше, пока не освободит все ресурсы `L_max` (`tyurin1985-full.txt:10579-10587`).

### 1.7. Виртуальный процесс пользователя и события

В ДИСПАК аппарат процессов перенесён с уровня ОС на уровень задачи пользователя программным путём и является виртуальным процессом более высокого уровня, чем аппарат процессов самой ОС (`tyurin1985-full.txt:10589-10593`).

Перевод процесса пользователя из блокировки в продолжение или готовность выполняет логический примитив типа флаг, называемый **событием** (`tyurin1985-full.txt:10595-10598`). Пользователю выделяются средства определить подмножество интересующих событий и место, куда передаётся информация о наступивших событиях; физически задаётся место в программе пользователя, куда ОС передаёт управление при появлении событий (`tyurin1985-full.txt:10599-10606`). Синхронизация процессов задачи пользователя построена на семафорных примитивах, разрешающих или запрещающих наступление событий (`tyurin1985-full.txt:10608-10611`). Накопление событий аддитивно, потери событий не происходит (`tyurin1985-full.txt:10611-10613`). Допустима многократная вложенность: событие `P₁` может наступить во время работы по `P₂`; восстановление уровня `n` после уровня `n + 1` происходит по окончании обработки `n + 1` (`tyurin1985-full.txt:10615-10620`).

## 4. 6.4. Системные экстракоды аппарата событий

### 4.1. Модель события

Аппарат событий идеологически повторяет внутренние и внешние прерывания ЭВМ и переносит их обслуживание с уровня аппаратуры и системы на уровень задачи пользователя (`tyurin1985-full.txt:11218-11224`). Событие: окончание обмена с лентой, диском, барабаном, образование подчинённой, срабатывание будильника, авария в задаче или подчинённой, сообщение от другой задачи или оператора, программные события, объявленные самой задачей, окончание вывода на терминал и другие (`tyurin1985-full.txt:11226-11233`). События наступают асинхронно (`tyurin1985-full.txt:11235-11236`). Обязательны указание места в доступной задаче, куда ОС передаёт управление, и программы-дешифратора, организующей переход на обработчик (`tyurin1985-full.txt:11236-11243`, OCR `ocr/page-0201.txt:1-5`). При событии естественное выполнение прерывается, а регистры состояния, СМ, адрес прерванного места и другая информация запоминаются в поле упрятывания (`tyurin1985-full.txt:11242-11247`).

Вложенность: если во время обработки события при разрешённых событиях наступит новое, поле упрятывания формируется снова (должно быть другим), а экстракод возврата восстанавливает только один уровень (`tyurin1985-full.txt:11249-11259`).

## 7. 6.7. Передача сообщений между задачами

### 7.1. Модель и терминология

Обмен большими порциями идёт через ВЗУ с синхронизацией по общему полю памяти, но для малых объёмов этот способ медленный (`tyurin1985-full.txt:12110-12117`). Аппарат сообщений работает в решении, передача есть обмен «память - память»: из буфера выдачи (БВ) одной задачи в буфер приёма (БП) другой (`tyurin1985-full.txt:12118-12126`, OCR `ocr/page-0216.txt:34-52`). Каждая задача может иметь до 255 БВ и столько же БП (`tyurin1985-full.txt:12136`). Порт совокупность одного БП и одного БВ, с номером и набором признаков; данные порта строка таблицы портов (ТП) (`tyurin1985-full.txt:12137-12142`). ТП расположена в ОП пользователя, её адрес сообщается ОС, и ТП есть полная характеристика задачи для аппарата сообщений (`tyurin1985-full.txt:12150-12153`).

### 7.2. Формат заголовка сообщения

Заголовок занимает первые два слова БВ; адресат: шифр задачи в первом слове, номер канала (разряды 17-22 второго слова), номер порта получателя (разряды 1-8), длина (разряды 37-48) (`tyurin1985-full.txt:12155-12167`, OCR `ocr/page-0217.txt:27-39`). Диаграмма рис. 6.1 распознана частично (`ocr/page-0217.txt:1-6`): `АБП`, `ШЗ`, `48 3736 25 24 22 17`, `ПР`, `ИК`. ⚠ OCR НЕ ПОДТВЕРЖДЕНО: полная разрядная схема рисунка. Надёжны только поля, описанные текстом выше.

БП работает гибче и реализует «почтовый ящик»; формат тот же, но поля `ШЗ`, `НП`, `ДЛ`, `ПК` имеют другой смысл (`tyurin1985-full.txt:12179-12184`). До получения сообщения в БП можно указать (`tyurin1985-full.txt:12186-12205`, OCR `ocr/page-0218.txt:14-33`):

| Условие | Кому можно принять сообщение |
|---|---|
| `ШЗ = 0, ПК = 0, НП ≠ 0` | только от порта `НП` любой задачи в решении |
| `ШЗ ≠ 0, ПК ≠ 0, НП = 0` | от любого порта задачи с шифром `ШЗ` на канале `ПК` |
| `ШЗ = 0, ПК = 0, НП = 0` | от любых портов любых задач в решении |
| `ШЗ ≠ 0, ПК ≠ 0, НП ≠ 0` | только от порта `НП` задачи `ШЗ` на канале `ПК` |

В OCR знаки «не равно» переданы как `#`, `40`, `520`; нормализация к `≠ 0` выполнена по смыслу перечисления (`tyurin1985-full.txt:12189-12203`). Допускаются и другие комбинации (`tyurin1985-full.txt:12205`). Относительный адрес приёма ОАП в разрядах 25-36 второго слова БП (`tyurin1985-full.txt:12207-12209`).
