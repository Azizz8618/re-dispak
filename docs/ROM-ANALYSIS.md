# Анализ дампов ПЗУ

Материалы: `rom/*.bin`, `rom/15bbb.rt5`. Полный отчёт воспроизводится командой:

```bash
python3 tools/analyze_roms.py
```

## `chargen-15ie.bin` — знакогенератор (КР556РТ5)

2048 байт, md5 `26fa93212f5b3043bd4b37d055af119a`.
Организация: **256 глифов × 8 строк × 7 точек**. Адрес глифа (код ВЗУ) —
старшие разряды адреса, строка — младшие. Каждый байт строки хранит точки
в разрядах 7…1 (`rows()` делает `>> 1`), старший из них — левая точка.

Примеры глифов (см. отчёт `analyze_roms.py`): `0x40 '@'`, `0x26 '&'`,
`0x30 '0'`, `0x41 'A'`, `0x5F '_'` — все читаются корректно.

### Организация КОИ7 Н1 в ПЗУ

Физические слоты ПЗУ (адресация `charset.rom_addr()`):

| Слоты ПЗУ | Содержимое | Коды КОИ7 Н1 |
|---|---|---|
| `0x00…0x1E` | **пусто** | — |
| `0x1F` | пустой слот | — |
| `0x20…0x7E` | пробел, цифры, знаки, латиница (верх./стр.) | те же |
| `0x7F` | сплошная заливка `█` | — |
| `0xC0…0xDE` | строчные русские а б ц … ч | `0x60…0x7E` (`rom_addr = 0xC0 + (code-0x60)`) |
| `0xE0…0xFE` | заглавные русские А Б Ц … Ч | `0x00…0x1E` (`rom_addr = 0xE0 + code`) |
| `0xFF` | пустой слот | — |

Слот `0x7F` в ПЗУ — полностью заполненный прямоугольник (все точки включены),
используется как непрозрачный блок / маркер. Ранее в коде для него
возвращалась заглушка `<7F>` — исправлено на `█` (см. `charset.label()`).

### Таблица КОИ7 Н1 (ГОСТ 27463-87)

Заглавные `0x00…0x1E`, строчные `0x60…0x7E` (порядок букв одинаков):

```
00:Ю 01:А 02:Б 03:Ц 04:Д 05:Е 06:Ф 07:Г 08:Х 09:И
0A:Й 0B:К 0C:Л 0D:М 0E:Н 0F:О 10:П 11:Я 12:Р 13:С
14:Т 15:У 16:Ж 17:В 18:Ь 19:Ы 1A:З 1B:Ш 1C:Э 1D:Щ
1E:Ч
```

Буква `Ё/ё` отсутствует в КОИ7 Н1 и передаётся как `Е/е`
(эмулятор нормализует `ё→е` при кодировании).

## `15bbb.rt5` — ПЗУ клавиатуры (КР556РТ5, контроллер 15ВВВ-97-006)

512 байт, md5 `1a36167da959bd4c77a9b324e34088d2`.
Содержит микропрограмму обхода ёмкостной матрицы и коды клавиш.
Заполненность `0xFF`: 46/512, уникальных байт 123.

Эмулятор использует файл как источник карты символов
(`keyboard.load_kbd_rom()`, `keyboard.lookup_key()`), базовая раскладка —
QWERTY/ЙЦУКЕН с КОИ7-выдачей.

## `dump1.bin` / `dump5.bin` — дампы ПЗУ блока логики (МПУ)

По 4096 байт. Энтропия по 256-байтовым блокам: значимые данные в начале
(≈6 бит/байт), нулевые хвосты `0x0A…0x0F`. Крупные зоны `0xFF` (маска/пусто):
`09FC+1540`, `06F0+11`, `0608+10`, `066C+10`, `0648+8`.

`dump1.bin` и `dump5.bin` различаются 728 байт в диапазоне `0x028F…0x0ACC`
(разные ревизии микропрограммы / разные экземпляры).

## Расшифровка ПЗУ блока логики (МПУ) — dump1/dump5

Расшифровка по документу **ЩЦМ3.778.012 ТО** «Дисплей алфавитно-цифровой
15ИЭ-00-013» (все таблицы — в `15ie.md`): ТАБЛИЦА 6 («профили» ППЗУ),
ТАБЛИЦА 7 (команды МПУ), ТАБЛИЦА 12 (режимы клавиатуры). Контекст —
разбор дефекта Н2 эмулятора ie15 (октябрь 2026).

### Формат и структура

- 4096×8. Рабочая зона dump1 — `0x000…0x9FB` (2556 байт), непрерывный
  0xFF-хвост с `0x9FC` (1540 байт); у dump5 код обрывается раньше —
  пустая зона `0x880…0x9C4`, хвост с `0xACD`. **Блок режимов/масок
  (см. ниже) существует только в dump1 — dump1 более полная ревизия.**
- Команды ТАБЛИЦЫ 7 (коды в скобках — octal) распознаются в 98%:
  `ADD 000-007`, `JMP 020-037` (однобайтовый, 4-бит операнд), `LDA 040-057`,
  `LCA 060` — **немедленная константа: следующий байт — операнд** (проверено
  статистикой: за `LCA` идут именно маски `0x1F, 0x3F, 0x60, 0x40, 0xDF,
  0xE0, 0x7F`), `ISZ 100-117` (счётчик + пропуск при −1 → циклы вида
  `ISZ; JMP`), `LIA 140-157` — чтение регистра ввода, `JMI 160-177` —
  прыжок по адресу из РОН, `SFC/SFS 200-216` — пропуск по флаге,
  `AND/XOR/CMP 220-277`, `SFR/SFT 300-317` — сброс/установка
  управляющего флага, `LDAa 320-337`, `STA 340-357`, `OTA 360-377` —
  регистры вывода.

### Ключевые находки

1. **Стартовый/режимный блок `0x06A…0x086`**: `CLA; УСТ ф0; OTA ВЫ13;
   LIA ВВ7; СБРОС ф1; СБРОС ф3; УСТ ф4; OTA ВЫ15; CLA` — инициализация
   режимов (флаги 0–7) и чистка РОН (`STA Р0-Р4, Р8-Р13`).
2. **Режимная развилка — флаг №5**: сразу после каждого чтения ввода
   (`LIA ВВ12/ВВ11/ВВ15…`) — `SFC/SFS ф5` и ветвление, часто
   `JMI [Р13]`. Флаг ставится/сбрасывается программой лишь в трёх
   местах (`0x1E0`, `0x515` — сбросы; `0x8DA` — установка), и при
   установке (`0x8DA`) выполняется `Р4 = 0xE0+Р7; Р8 ^= 0x40` —
   переключение режима сопровождается инверсией разряда 0x40 рабочего
   кода (КОИ7-заглавные `0x40-0x5E` ↔ ЭВМ `0x00-0x1E`).
3. **Кодовые срезы (адреса dump1)**: `AND 0x1F` — `0x6A8, 0x6C2, 0x6DA,
   0x6E7, 0x739, 0x741, 0x8D2` — универсальное приведение КОИ7 к коду
   ЭВМ (и `0x4A` Й-верх, и `0x6A` й-низ дают `0x0A` — регистр
   сливается); `XOR 0x40` — `0x8E7`; `AND 0xDF` (снятие бита 0x20) —
   `0x8AD`; базы регистров `0x40/0x60` — `0x2B6, 0x340, 0x462, 0x889`.
4. **Диспетчеры**: `JMI [Р5]` (самая частая), `[Р13]/[Р14]/[Р15]` — с
   условными развилками по флагам 0/1/2/6; адреса строятся формулой
   `LCA <база> + Р7`, базы таблиц: `0x40, 0x90, 0xC8, 0xE0` (построения
   по адресам `0x462, 0x8DD-0x8F3`); Р7 сверяется с границами
   `0x19/0x1A/0x59`.
5. **Единственная явно читаемая цепочка «вход → маска → линия»** —
   `0x51D…0x523`: `СБРОС ф5 → LIA ВВ0 → AND Р5 → условие → OTA ВЫ14`.
6. **ТАБЛИЦА 12**: режимы клавиатуры — `ЛАТ/РУС/ДУШ/СДВ/ДК` (сигналы
   ВИ7Н, ВВ12Н, ВВ14Н, ВВ15Н, ВВ16Н); отдельного состояния «Shift/
   регистр» в терминале **нет** — Shift применяется внутри ПЗУ
   клавиатуры (`15bbb.rt5`), терминал получает уже сдвинутый код и
   обрабатывает его режим-флагами и срезами выше.

### Открытые вопросы (почему полный CFG не построен)

- **адресация `JMP`** — «Решение ПЗУ, находящейся на странице YYY по
  адресу YYY»: таблицы страниц в документе нет, цели переходов не
  разрешаются;
- **недокументированные опкоды** — `0x08-0x0F`, `0x18-0x1F`, часть
  `0x31-0x3F`, `0x54-0x5C` (по позиции — условные пропуски/переходы,
  но формально их в ТАБЛИЦЕ 7 нет);
- **семантика ВВ-регистров** — данные клавиатуры или режим-сигналы
  (ТАБЛИЦА 12 использует те же обозначения: «РУС → ВВ12Н»);
- без этих пунктов маршрут «конкретный входной код → строка» не
  доказывается: общая модель (режим-флаги + срезы, Shift — в клавиатуре)
  подтверждена, конкретная строка — нет. Для вопроса Н2 правка сделана
  по спецификации набора и практике КРАБа (см. ie15: Н2-регистр не
  важен), ПЗУ ей не противоречит.
