1. ОБЗОР СИСТЕМЫ КОМАНД
========================

Система команд разделена на 5 категорий:
  1. Документирование — работа с комментариями
  2. Анализ — изучение кода и процедур
  3. Трассировка — разбор выполнения программ
  4. Отладка — исправление и тестирование
  5. Навигация — перемещение по файлам и вывод

Краткие синонимы (для экономии токенов):
  ПКФ  — ПРОКОММЕНТИРУЙ ФАЙЛ
  ОБЪ  — ОБЪЯСНИ
  ПС   — ПОДГОТОВЬ СПРАВОЧНИК
  ТР   — ПРОАНАЛИЗИРУЙ ТРАССУ
  ТРЭ  — ПРОАНАЛИЗИРУЙ ТРАССУ ЭМУЛЯТОРА
  ОТЛ  — ОТЛАДИТЬ ЭМУЛЯТОР
  ИСП  — ИСПРАВЬ
  СЛД  — СЛЕДУЮЩИЕ
  ВФЗ  — ВЫДАЙ ФРАГМЕНТ ЗАНОВО
  РЗВ  — РЕЗЕРВНАЯ КОПИЯ КОНФИГУРАЦИИ


2. КОМАНДЫ ДОКУМЕНТИРОВАНИЯ
============================

2.1 ПРОКОММЕНТИРУЙ ФАЙЛ
-----------------------
Синтаксис:
  ПРОКОММЕНТИРУЙ ФАЙЛ <module.be>
  ПКФ <module.be>

Действия:
  1. Открыть файл из корневой папки проекта
  2. Проанализировать структуру модуля
  3. Добавить заголовок модуля (если отсутствует)
  4. Прокомментировать каждую процедуру порциями
     по 120 строк
  5. Записать изменения в файл
  6. Выполнить: ./asm.pl module.be
  7. Проверить отсутствие ошибок компиляции
  8. Если есть зонгп — выполнить верификацию
  9. Все зоны должны совпадать ("matches")
  10. При ошибках — исправить и повторить

Результат: Полностью документированный и
           верифицированный модуль

Пример:
  > ПРОКОММЕНТИРУЙ ФАЙЛ kachka.be
  > ПКФ kachka.be


2.2 ПРОКОММЕНТИРУЙ ПРОЦЕДУРУ
-----------------------------
Синтаксис:
  ПРОКОММЕНТИРУЙ ПРОЦЕДУРУ <ИМЯ> [В <module.be>]

Действия:
  1. Найти определение процедуры
  2. Добавить детальный комментарий
  3. Проверить компиляцию

Результат: Документированная процедура

Пример:
  > ПРОКОММЕНТИРУЙ ПРОЦЕДУРУ ТП1 В kachka.be


2.3 ДОБАВЬ ЗАГОЛОВОК МОДУЛЯ
----------------------------
Синтаксис:
  ДОБАВЬ ЗАГОЛОВОК <module.be>

Действия:
  1. Прочитать modloc.txt для определения адреса
  2. Сформировать заголовок по шаблону
  3. Вставить в начало файла
  4. Проверить компиляцию

Результат: Модуль с заголовком


2.4 СИНХРОНИЗИРУЙ С TEXT
-------------------------
Синтаксис:
  СИНХРОНИЗИРУЙ <module.be> С TEXT

Действия:
  1. Проверить наличие text/module.be
  2. При различиях — скопировать module.be
     в text/module.be
  3. Сообщить о результате

Результат: Синхронизированная копия в text/


3. КОМАНДЫ АНАЛИЗА
==================

3.1 ОБЪЯСНИ
-----------
Синтаксис:
  ОБЪЯСНИ <ПРОЦЕДУРУ> [В <module.be>]
  ОБЪ <ПРОЦЕДУРУ>

Действия:
  1. Найти определение процедуры
  2. Собрать все вызываемые процедуры
  3. Построить блок-схему алгоритма
  4. Описать используемые регистры
  5. Описать входные/выходные параметры
  6. Выдать развёрнутый отчёт

Результат: Детальное описание алгоритма
           с блок-схемой

Пример:
  > ОБЪЯСНИ ЗАХЗАН
  > ОБЪ ЗАХЗАН


3.2 ПОКАЖИ ВЫЗОВЫ
-----------------
Синтаксис:
  ПОКАЖИ ВЫЗОВЫ <СИМВОЛА>
  ГДЕ ВЫЗЫВАЕТСЯ <СИМВОЛ>

Действия:
  1. Выполнить search_codebase по всем файлам
  2. Собрать все вхождения символа
  3. Группировать по модулям
  4. Выдать таблицу результатов

Результат: Таблица всех ссылок на символ

Пример:
  > ПОКАЖИ ВЫЗОВЫ ЗАХЗАН
  > ГДЕ ВЫЗЫВАЕТСЯ ШГП


3.3 НАЙДИ
---------
Синтаксис:
  НАЙДИ <ПАТТЕРН>

Действия:
  1. Выполнить search_codebase с regex
  2. Выдать все совпадения с контекстом

Результат: Список найденных фрагментов

Пример:
  > НАЙДИ "УИА '2003'"
  > НАЙДИ "ШКНП\\s+\\d+"


3.4 ГДЕ ИСПОЛЬЗУЕТСЯ
--------------------
Синтаксис:
  ГДЕ ИСПОЛЬЗУЕТСЯ <ПЕРЕМЕННАЯ>

Действия:
  1. Найти все чтения переменной
  2. Найти все записи в переменную
  3. Разделить на категории

Результат: Таблица использования переменной

Пример:
  > ГДЕ ИСПОЛЬЗУЕТСЯ М27


3.5 ПОДГОТОВЬ СПРАВОЧНИК
-------------------------
Синтаксис:
  ПОДГОТОВЬ СПРАВОЧНИК <module.be> [ДЛЯ ИИ]
  ПС <module.be>

Действия:
  1. Прочитать файл модуля
  2. Извлечь заголовок (если есть)
  3. Собрать все метки (определения символов)
  4. Найти все внешние ссылки (ДИСП70 ВНЕШ,
     КАЧКА ВНЕШ и т.д.)
  5. Определить точки входа по переходам
  6. Сформировать структурированный справочник:
     - Имя модуля, зона загрузки, адрес
     - Точки входа (экспорт)
     - Внешние ссылки (импорт)
     - Таблица символов
     - Ключевые переменные
     - Регистры, используемые в модуле
  7. Записать справочник в module.ref
  8. Или вывести в формате для вставки в AGENTS.md

Результат: Файл module.ref со справочником модуля

Пример:
  > ПОДГОТОВЬ СПРАВОЧНИК disp70.be
  > ПС kachka ДЛЯ ИИ

Пример:

Результат: Анализ расхождений

Пример:

  3. Показать в таблице

Результат: Состояние регистров в точке

Пример:
  > ПОКАЖИ РЕГИСТРЫ В 00720

Действия:

Действия:
  1. Найти тест в папке tests/
  2. Определить опции из options.txt
  3. Выполнить dispak с опциями
  4. Сравнить вывод с output.txt

Результат: Отчёт о выполнении теста

Пример:

5.3 ПРОВЕРЬ МОДУЛЬ
------------------
Синтаксис:
  ПРОВЕРЬ МОДУЛЬ <ИМЯ>

  1. Выполнить ./asm.pl <имя>.be
  2. Проверить отсутствие ошибок

Результат: Отчёт о состоянии модуля

Пример:
  > ПРОВЕРЬ МОДУЛЬ disp70


5.4 ОТЛАДИТЬ ЭМУЛЯТОР
---------------------
Синтаксис:
  ОТЛАДИТЬ ЭМУЛЯТОР [опции]
  ОТЛ ЭМУ [опции]

Опции:
  -t, --trace N   — включить трассировку с пульта N
  -b, --break     — останов на первой команде
  -v, --visual    — визуальный режим отладчика
  -p, --port N    — порт терминала (по умолч. 4202)
  -c, --config F  — конфигурационный файл

Действия:
  1. Проверить наличие запущенного эмулятора
  2. Если запущен — подключиться к screen-сессии
  3. Если нет — запустить: ../../BIN/besm6 dispak.ini
  4. В режиме останова:
     - Установить пульт: set pult=N
     - Запустить: run
     - Останов по Ctrl+G
  5. Извлечь трассу из лога

Команды отладчика SIMH:
  +----------------+----------------------------------+
  | Команда        | Действие                         |
  +----------------+----------------------------------+
  | run            | Запуск с текущего адреса         |
  | run NNNN       | Запуск с адреса NNNN (8-ричное)  |
  | step           | Шаг (одна команда)               |
  | step N         | N шагов                          |
  | cont           | Продолжить выполнение            |
  | br             | Показать точки останова          |
  | br NNNN        | Установить точку останова        |
  | br -r NNNN     | Удалить точку останова           |
  | br -c          | Удалить все точки останова       |
  | ex NNNN        | Просмотр памяти по адресу        |
  | ex NNNN-NNNM   | Просмотр диапазона памяти        |
  | de NNNN V      | Запись значения в память        |
  | set pult N     | Установить пульт трассировки     |
  | set pult 0     | Выключить трассировку            |
  | set throttle N | Ограничить скорость (MIPS)       |
  | show dev       | Показать состояние устройств     |
  | show clock     | Показать счётчик команд          |
  | show cpu       | Показать состояние процессора    |
  | show break     | Показать точки останова          |
  | boot           | Загрузка с устройства            |
  | quit           | Выход из эмулятора               |
  +----------------+----------------------------------+

Управление трассой:
  - set pult 11   — трассировка экстракодов и ПВ
  - set pult 15   — детальная трассировка команд
  - set pult 17   — максимальная трассировка
  - Лог трассы: debug.txt (из dispak.ini)
  - Лог консоли: log.txt

Формат трассы (из debug.txt):
  СчАС: КОП адрес [ИР] результат
  Пример: 00123: 05 04567 [15] 000000000001

Примеры:
  > ОТЛАДИТЬ ЭМУЛЯТОР
  > ОТЛ ЭМУ -t 15
  > ОТЛ ЭМУ -b -v
  В консоли эмулятора:
    sim> set pult 15
    sim> run
    (выполнение)
    Ctrl+G
    sim> set pult 0
    sim> quit
  > ПРОАНАЛИЗИРУЙ ТРАССУ debug.txt

Результат: Интерактивный отладочный сеанс


5.5 АНАЛИЗ ТРАССЫ ЭМУЛЯТОРА
---------------------------
Синтаксис:
  ПРОАНАЛИЗИРУЙ ТРАССУ <файл>
  ТРЭ <файл>

Действия:
  1. Прочитать файл трассы
  2. Извлечь последовательность команд
  3. Определить переходы и вызовы
  4. Построить граф выполнения
  5. Выделить ключевые моменты:
     - Точки входа в процедуры
     - Экстракоды
     - Изменение регистров
     - Обращения к памяти

Формат вывода:
  СчАС КОП адрес: результат [примечание]

Пример:
  > ПРОАНАЛИЗИРУЙ ТРАССУ debug.txt
  > ТРЭ ~/Yandex.Disk/simh/BESM6/OSZAGR/debug.txt


6. КОМАНДЫ НАВИГАЦИИ
====================

6.1 СЛЕДУЮЩИЕ
-------------
Синтаксис:
  СЛЕДУЮЩИЕ [N] СТРОК
  СЛД [N]

Действия:
  1. Продолжить вывод с последней показанной
     позиции
  2. Вывести N строк (по умолчанию 60)
  3. Запомнить новую позицию

Результат: Продолжение вывода файла

Пример:
  > СЛЕДУЮЩИЕ 120 СТРОК
  > СЛД 200


6.2 ВЫДАЙ ФРАГМЕНТ ЗАНОВО
-------------------------
Синтаксис:
  ВЫДАЙ ФРАГМЕНТ ЗАНОВО [С СТРОКИ N]
  ВФЗ [С N]

Действия:
  1. Вернуться к началу предыдущего фрагмента
  2. Вывести с учётом последних изменений
  3. Если указана строка N — начать с неё

Результат: Повторный вывод фрагмента

Пример:
  > ВЫДАЙ ФРАГМЕНТ ЗАНОВО
  > ВФЗ С 500


6.3 ПОКАЖИ СПРАВОЧНИК
---------------------
Синтаксис:
  ПОКАЖИ <СПРАВОЧНИК>

Доступные справочники:
  RUKAVA — Архитектура БЭСМ-6, структура ОС
  RUKAV1 — Параметры конфигурации, тесты
  RUKDKS — Модификация КАДОПАМ, ДКС

Действия:
  1. Загрузить указанный файл из RUKAVA/
  2. Показать оглавление или раздел
  3. Извлечь релевантную информацию

Результат: Извлечение из справочника

Пример:
  > ПОКАЖИ RUKAVA РАЗДЕЛ "ЭКСТРАКОДЫ"
  > ПОКАЖИ RUKDKS ПРОТОКОЛ ДКС


7. АВТОМАТИЧЕСКИЕ ДЕЙСТВИЯ
==========================

При получении команды агент автоматически:
  1. Создаёт .bak перед любым изменением файла
  2. Проверяет размер файла (изменение >10%
     — признак ошибки)
  3. Выполняет компиляцию после изменений
  4. Запоминает прочитанные файлы в кэш

10. СООБЩЕНИЯ ОБ ОШИБКАХ

При невозможности выполнить команду агент
сообщает:
  - "НЕДОСТАТОЧНО ДАННЫХ: <причина>"
  - "ФАЙЛ НЕ НАЙДЕН: <путь>"
  - "ОШИБКА КОМПИЛЯЦИИ: см. <файл>.lst"
  - "НЕСОВПАДЕНИЕ ЗОН: см. verify.pl"


10. ССЫЛКИ
==========

- .clinerules — Правила проекта
- AGENTS.md — Инструкции для агента
- modloc.txt — Карта загрузки модулей
- rvs.src — Раскрой внешних связей
- module.ref — Справочник модуля (генерируется)


11. ФОРМАТ СПРАВОЧНИКА МОДУЛЯ
==============================

Справочник (файл .ref) содержит структурированную информацию
о модуле для использования ИИ в других сессиях.

Пример справочника для модуля ДИСП70:
