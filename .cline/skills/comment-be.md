# Навык: Комментирование .be файлов (comment_be.py)

## 1. Назначение

Комментирование `.be` файлов (исходники БЕМШ/МАДЛЕН) выполняется **в два этапа**
с итеративной сборкой до устранения всех ошибок.

## 2. Жизненный цикл

```
имя_модуля.be           ← исходный файл
        │
        ├─ сохраняется в  имя_модуля_bak.be
        │
        ▼
   ╔═══════════════════════════════════════╗
   ║  Этап 1 — Автоматический (скрипт)     ║
   ║  comment_be.py                        ║
   ╚═══════════════════════════════════════╝
        │
        ▼
имя_модуля_commented.be  ← инлайн-комментарии + шапки процедур + шапка модуля
        │                   (машинный код не меняется)
        ▼
   ╔═══════════════════════════════════════╗
   ║  Этап 2 — ИИ-анализ                  ║
   ║ углублённое комментирование          ║
   ╚═══════════════════════════════════════╝
        │
        ▼
имя_модуля_edited.be     ← дополненная общая шапка модуля, связи с другими
        │                   модулями, уточнённые шапки процедур, строчные
        │                   комментарии
        ▼
   ╔═══════════════════════════════════════╗
   ║  Финальная проверка                   ║
   ║  perl asm.pl файл.be                  ║
   ╚═══════════════════════════════════════╝
        │
        ├─ ошибки = 0 → подтверждение пользователя
        │                    │
        │                    ▼
        │              cp имя_модуля_edited.be → имя_модуля.be
        │              make clean && make
        │                    │
        │                    ├─ ошибки = 0 → ✅ готово
        │                    └─ ошибки > 0 → устранить, повторить проверку
        │
        └─ ошибки > 0 → устранить, повторить проверку
```

### Этап 1 — Автоматический (скрипт `comment_be.py`)
Скрипт добавляет:
- **Инлайн-комментарии** к каждой инструкции (описание операции, расшифровка операнда)
- **Шапки процедур** — блоки `*****` перед каждой процедурой с регистрами, входами/выходами
- **Шапку модуля** — имя, СТАРТ, ВХОД, ВНЕШ

Выход: `имя_модуля_commented.be`. Машинный код не меняется.

### Этап 2 — ИИ-анализ (углублённое комментирование)
После автоматического прохода ИИ анализирует прокомментированный файл и дополняет:

1. **Общая шапка модуля** — описание внутренней логики и архитектуры модуля:
   - назначение модуля, общая схема работы
   - основные потоки управления
   - используемые структуры данных и буферы
   - глобальные переменные и их роль

2. **Шапки процедур** — дополнения на основе анализа:
   - описание алгоритма процедуры
   - связи с другими модулями (вызовы ВНЕШ-процедур, возвраты)
   - протокол вызова (входные/выходные параметры, соглашения)
   - восстановление контекста (какие регистры сохраняются/восстанавливаются)

3. **Строчные комментарии** — при необходимости:
   - уточнение неочевидных инструкций (побитовые операции, арифметика сдвигов)
   - расшифровка магических констант
   - пояснение циклов и условных переходов
   - связи с внешними модулями на уровне отдельных инструкций

Выход: `имя_модуля_edited.be`.

### Финальная проверка и сборка
1. `perl asm.pl имя_модуля_edited.be` — проверка на ошибки ассемблера
2. Если ошибок > 0 — устранить и повторить проверку
3. Если ошибок = 0 — показать пользователю diff с оригиналом, запросить подтверждение
4. При подтверждении: `cp имя_модуля_edited.be → имя_модуля.be`
5. `make clean && make`
6. Если `make` завершился с ошибками — устранить и повторить цикл
7. Цикл завершается только при 0 ошибок

### Порядок имён файлов
| Файл | Назначение |
|------|------------|
| `имя_модуля_bak.be` | Оригинал (создаётся один раз, не перезаписывается) |
| `имя_модуля_commented.be` | Результат этапа 1 (скрипт) |
| `имя_модуля_edited.be` | Результат этапа 2 (ИИ) |
| `имя_модуля.be` | Финальный файл (заменяется после проверки) |

## 4. Что генерирует

### 4.1. Шапка модуля (после СТАРТ)
```
***************************************************
* Модуль ЭКВВОД  СТАРТ='10000'                    *
*   ВХОД (46): КОН, КОНЕЦ, КНЦ, ...              *
*   ВНЕШ (52): ЭК2, ЭК3, ЭК4, ...                *
***************************************************
```

### 4.2. Шапки процедур (НОП/BSS маркер или ПБ/UJ граница)
```
***************************************************
* Э131                                            *
*   Регистры: М3, М4, М6, М10, М12, М13, М14     *
*   Вход: ВЭ131, G10737, ПП1                      *
*   Выход: (М15), ТБУФ(М15), ФИЗОБМ(М16)         *
***************************************************
```

### 4.3. Инлайн-комментарии (столбец 40)
```
КВ ЗП 34(М3)                              ,34 := СМ
 ПБ КОНЕЦ1                                ,переход на КОНЕЦ1
```

## 5. Детекция процедур

Процедуры определяются по двум маркерам:
- **НОП (БЕМШ) / BSS (МАДЛЕН)** — начало процедуры, шапка вставляется после него
- **ПБ (БЕМШ) / UJ (МАДЛЕН)** — безусловный переход, конец процедуры

**Дополнительные маркеры выхода:** `ПО`, `ПЕ`, `ПИО`, `ПИНО`, `UZA`, `UIA`, `VZM`, `VIM`

Fallback: если нет НОП/BSS, процедура начинается с `label + instruction`.

Для каждой процедуры собираются:
- **Регистры** (М2-М17) — по упоминаниям в коде
- **Входные точки** — метки внутри процедуры
- **Выходные точки** — цели `ПБ`/`ПВ`/`UJ`/`VJM`

### Идемпотентность
Скрипт идемпотентен: повторный запуск на уже прокомментированном файле
даёт идентичный результат (diff = 0). Достигнуто за счёт:
- `_strip_comment()` — удаление существующих комментариев по позиции запятой ≥20 колонок
- `gen()` очищает операнд от артефактов комментариев (начинающихся с `,`)
- `ic()` всегда добавляет ≥2 пробела перед запятой комментария
- Шапки процедур/модуля не дублируются (проверка наличия `*` блока)

### Файлы с макроопределениями (МАСRО/МЕND)
Файлы, содержащие макроопределения (`МАСRО`/`МЕND`), обрабатываются с ограничениями:
- **Шапки процедур и модуля** (`*` блоки) **не вставляются** — макроассемблер БЕМШ
  расширяет макросы и `*` строки попадают в контекст расширения, вызывая ошибки.
- **Строки внутри `МАСRО`..`МЕND`** пропускаются полностью (без комментариев).
- **Инлайн-комментарии** (`,comment`) добавляются к строкам вне макроопределений.
- Примеры файлов: `serp4.be`, `ekvvod.be`, `bonbot.be`, `plan.be`, `prikaz.be` и др.
- Определение: файл считается макросодержащим, если содержит строку, начинающуюся
  с `МАСRО`, `МАКРО` или `MACRO`.

## 6. Опция --apply

После генерации скрипт спрашивает, применить ли результат
к исходнику. При `y` копирует `_commented.be` → оригинал.

**Примечание:** в рамках двухэтапного процесса `--apply` не используется
на этапе 1. Замена оригинала происходит только после этапа 2 (ИИ-анализ),
проверки `asm.pl` и `make clean && make` с 0 ошибок.
