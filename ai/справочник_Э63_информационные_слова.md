=====================================================================
## 1. МЕХАНИКА ВЫЗОВА (контракт, который должен реализовать эмулятор)
=====================================================================

Инструкция `Э63 А` (код операции 63₈):

1. Исполнительный адрес А вычисляется обычным образом (БРЗ, индексация)
   и попадает в индекс-регистр М16. Задаче возвращается результат тоже
   через М16 — поэтому после любого Э63 регистр М16 «не определён»
   (Dispak-programmer-guide.md:1999-2001).
2. Внутреннее прерывание: переход на ячейку 513₈ = 500₈ + (63₈ − 50₈)
   (векторы: Э50→500₈ … Э77→527₈; ai/справочник_ДИСП70.md §8).
3. Заглушка ДИСП70 (disp70.be:321-323):
   `зп СМ` — сумматор задачи сохраняется в ячейку СМ;
   `пб Э63` — переход в ХЛАМ.
4. Обработчик ХЛАМ (khlam.be:2324-2363):
   - `счмр 64; зп РМР` — РМР задачи сохраняется в ячейку РМР;
   - `счрж 31; или П23; зп РК` — установка признака «это Э63»;
   - `счи М16; зп И16` — адрес ИС запоминается в И16;
   - `сч Е18; пв ПЕЭКС(М16)` — проверка перехвата (шкала перехвата,
     бит 8 = «перехват э63,э66,э62,э61,э67», Dispak-description.md:1235);
     при перехвате вызов уводится в ПЕРЕХ родительской задачи;
   - `сч СМ; нтж КЛЮЧАР` — сумматор задачи сравнивается с 'КЛЮЧАР':
     * НЕ СОВПАЛО → `пб Э72` (vzu.be:1948): `сч Е31; пб ВЫЗОВ` —
       вызов нерезидента РЕСУРС (Е31 — его разряд ШГ,
       disp70.be:605 «Е31-РЕСУРС»; ВЫЗОВ — boek1.be:2124). По этому
       пути работают ВСЕ не-архивные функции Э63:
         - АИСП = 0..4 — временные функции (см. §5.5);
         - АИСП >= 10₈ — запрос содержимого физической ячейки ОЗУ
           по адресу АИСП (programmer-guide §5.3.187);
     * СОВПАЛО → архивный путь:
         - проверка занятости архива (ЕЗАР, СЕМАРХ, ШКЭ70А/ТАФ);
         - НЕАРХ (khlam.be:2351-2363): `сч (М16)` — чтение ИС с
           контролем принадлежности листа памяти задаче (авост
           «ЧИСЛО В ЧУЖ.ЛИС»), РМР → ИНФСЛП слова ИПЗ, бит 47
           слова 41 ИПЗ, загрузка нерезидента АРФА;
         - АРФА (arfa.be, вход ВХАР → ПОЭК → G70133) читает
           `сч (М16)` — первое инфослово — и разбирает его.
5. Возврат в задачу: М16 = 0 при нормальном завершении, иначе — код
   ответа (§6). СМ, РМР и установленная группа операций после вызова
   не определены.

Дерево диспетчеризации:

    Э63 А, М16 := А
    │
    ├─ перехват разрешён? ──→ ПЕРЕХ родительской задачи
    │
    ├─ СМ(задачи) = 'КЛЮЧАР' (в'1242547515620060')?
    │    │
    │    ├─ НЕТ:  А < 10₈  → временные функции 0..4 (РЕСУРС)
    │    │       А ≥ 10₈  → чтение физ. ячейки ОЗУ по адресу А
    │    │
    │    └─ ДА:   АРХИВ: ИС = слово по адресу А,
    │            тип работы = разряды 48-43 слова ИС
    └─ дальше по типу работы (таблица §4)

## 3. СТАНДАРТНАЯ СТРУКТУРА СЛОВА ИС
=====================================================================

(sysprog-guide §8.7.1.1; подтверждается perekh.be:1715, 1764-1778,
serp5.be:1195-1198)

    разряды: 48…43 42…37 36……25   12    4…1
             ┌──────┬──────┬────────┬─────┬──────┐
             │ тип  │ вирт.│ пароль │ пр. │ хар- │
             │работы│ номер│        │чтения│ имени│
             └──────┴──────┴────────┴─────┴──────┘
    октет:    [1-2]  [3-4]  [5-8]   [13]  [15-16]

- 48-43 — тип работы (код операции архивной системы): 01…31, 61;
- 42-37 — виртуальный (логический) номер области, 0 = не задан;
- 36-25 — пароль (12 разрядов = 4 восьмеричные цифры);
- 12 — признак чтения (смысл зависит от операции: дозаказ на чтение,
  смена/подтверждение пароля чтения и т.п.);
- 4-1 — характеристика имени (способ задания имени).

НЕОПИСАННЫЕ разряды должны быть нулевыми, иначе авост
«ОШ.В ИНФ.СЛ.ЭКСТ».

### 3.1. Характеристика имени (разряды 4-1)

| Значение | Способ задания имени                                   |
|----------|--------------------------------------------------------|
| 0        | имени нет: область задана вирт.номером, либо идентификатором в ИС+1 (способ 4) |
| 1…7      | «по-старому»: число простых имён                        |
| 10       | «по-новому» в коде УПП (текст, терминатор ';' или 377₈) |
| 14       | «по-новому» в коде МС-80 (терминатор 012₈)              |
| 17       | ⚠ по sysprog §8.7.1.1 «все единицы» = код ISO; в programmer-guide §5.2 этого значения нет — проверить |

Правило: если операции允许 и вирт.номер, и имя, то либо 42-37 = 0,
либо 4-1 = 0; оба нуля трактуются как идентификатор в ИС+1.

### 3.2. Имя «по-старому» (1…7)

    ИС+1:      символы 1-6 первого простого имени (УПП, по 8 разрядов);
    ИС+2: 48-25 — символы 7-9;
          24-1  — шифр хозяина области (дв.-десят., 6 цифр) или 0;
    ИС+3, ИС+4, … — последующие простые имена (те же 2 слова,
    но в 24-1 второго слова — нули).

### 3.3. Имя «по-новому» (10/14)

Текст `ИМЯ1.ИМЯ2.…` в коде УПП (или МС-80) в словах ИС+1, ИС+2, …
по 6 символов на слово. Пропускаемый символ: 143₈ (УПП) / 000₈ (МС-80).
Терминатор: ';' или 377₈ (УПП) / 012₈ (МС-80). До 17₈ слов.

Реальный пример из ОС (perekh.be:1775-1778, запрос сведений об области
файла статистики ПЕРЕХВАТ):

    ИНФСТ КОНД В'0700000000000010'      , тип 07, имя «по-новому» УПП
           КОНД П'АRFА.П'
           КОНД П'ЕРЕХВА'
           КОНД П'Т00000'М32В'377'      , 'Т' + терминатор 377

### 3.4. Идентификатор области («ссылка», способ 4)

    ИС+1:  34 Р = 1
           33-18 Р — внутреннее имя области
           17 Р = 0
           16-10 Р — продолжение внутреннего имени
           9-1 Р = '356'(8)

Внутреннее имя можно получить заранее через Э50 '105' или операцию 13.

## 4. ТАБЛИЦА ОПЕРАЦИЙ (тип работы → информационные слова)
=====================================================================

Формат: ИС (поверх стандартной структуры), РМР, выход. Поля, не
указанные для операции, должны быть нулевыми.

### 01 — создание области (§8.7.2.1, 5.3.156)
    ИС:  4-1 — способ имени;  ИС+1… — имя
    РМР: 22-21 — номер группы; 20-18 — вид области;
         17 — признак индивидуальной области; 16-1 — длина (в зонах)
    Выход: М16 = 0 / код ответа
    ⚠ programmer-guide §5.3.156 для РМР даёт также «22-21 группа,
    20-18 вид, 17 инд., 16-1 длина»; sysprog §8.7.2.1 добавляет
    «48-25 — шифр хозяина области» — расхождение проверить по arfa.be.

### 02 — уничтожение области (§8.7.2.2, 5.3.157)
    ИС: 36-25 — пароль записи; 4-1 — способ имени; ИС+1… — имя
    РМР: = 0

### 03 — установка/смена/снятие пароля (§8.7.2.3, 5.3.158)
    ИС: 42-37 — вирт.номер; 36-25 — старый пароль записи;
        24-13 — новый пароль; 12 — 0 = пароль записи / 1 = пароль чтения;
        4-1 — способ имени; ИС+1… — имя

### 04 — задание прав доступа (§8.7.2.4, 5.3.159)
    ИС: 42-37 — вирт.номер; 36-25 — пароль записи;
        4-1 — способ имени; ИС+1… — имя
    РМР: 48-25 — шифр, которому предоставляются права (0 = «все прочие»);
         2-1 — права: 0 = «НЕТ», 1 = «ЧТ», 2 = «ЗП», 3 = «МОН»

### 05 — подтверждение пароля (§8.7.2.5, 5.3.160)
    ИС: 42-37 — вирт.номер; 36-25 — пароль;
        12 — 0 = запись / 1 = чтение; 4-1 — способ имени; ИС+1… — имя

### 06 — запрос списка допущенных лиц (§8.7.2.6, 5.3.161)
    ИС: 42-37 — вирт.номер; 36-25 — пароль чтения;
        4-1 — способ имени; ИС+1… — имя
    РМР: 15-1 — адрес буфера из 4 слов для ответа
    Ответ (В+0): 5 Р — права «прочих»; 12-11 … 2-1 — права шифров 1-6;
         В+1…В+3 — шифры 1-6 (по два на слово: 48-25 и 24-1)

### 07 — запрос сведений об области (§8.7.2.7, 5.3.162)
    ИС: 42-37 — вирт.номер; 4-1 — способ имени; ИС+1… — имя
    Выход на СМ: 48-25 — шифр бюджета; 24 — есть пароль чтения;
        23 — есть пароль записи; 22-18 — тип области; 16-1 — длина

### 10 — запрос каталога областей (§8.7.2.8, 5.3.163)
    ИС: 5 Р — признак верхнего уровня (тогда 4-1 = 0);
        иначе 4-1 — способ имени; ИС+1… — имя области-каталога
    РМР: 48-37 — количество запрашиваемых имён;
         36-25 — начальный номер запрашиваемого имени

### 11 — запрос каталога общих областей (§8.7.2.9, 5.3.164)
    Формат полностью аналогичен 10.

### 12 — дозаказ области (§8.7.2.10, 5.3.165)
    ИС: 42-37 — вирт.номер (0 = взять первый свободный из шкалы РМР);
        12 — признак чтения; 4-1 — способ имени; ИС+1… — имя
    РМР: шкала свободных виртуальных номеров:
         разряд 48 = ВН'30', 47 = ВН'31', 46 = ВН'32', …
    Выход: М16 = 0; СМ — виртуальный номер, на который прошёл дозаказ

### 13 — запрос имени и идентификатора области (§8.7.2.11, 5.3.166)
    ИС: 42-37 — вирт.номер; 4-1 — способ имени; ИС+1… — имя
    РМР: 15-1 — адрес буфера для имени (0 = нужен только идентификатор)
    Выход: СМ 34-1 — идентификатор; буфер — имя «по-новому» УПП
        (до 17₈ слов, терминатор 377₈)

### 14 — установка сдвига по области (§8.7.2.12, 5.3.167)
    ИС: 42-37 — вирт.номер; 21 — признак отрицательного сдвига;
        20-5 — абсолютная величина сдвига (в зонах);
        4-1 — способ имени; ИС+1… — имя

### 15 — запрос сдвига (§8.7.2.13, 5.3.168)
    ИС: 42-37 — вирт.номер
    Выход: ответ на СМ

### 16 — переход в режим администратора (§8.7.2.14, 5.3.169)
    ИС: 48-43 = 16;  ИС+1: 48-1 — ключ администратора в УПП
    РМР: 48-25 — шифр бюджета

### 17 — смена ключа и шифра администратора (§8.7.2.15, 5.3.170)
    ИС: 24-1 — шифр администратора;
        ИС+1: 48-1 — новый ключ; ИС+2: 48-1 — старый ключ (УПП)
    РМР: 48-25 — шифр бюджета

### 20 — создание бюджета (§8.7.2.16, 5.3.171)
    ИС: 24-1 — шифр администратора нового бюджета
    РМР: 48-25 — шифр создаваемого бюджета

### 21 — задание ресурсов бюджета (§8.7.2.17, 5.3.172)
    ИС: 26-25 — вид ресурса (1 — резидентный, 2 — нерезидентный,
        3 — «ленточный»); 24-1 — число зон
    РМР: 48-25 — шифр бюджета

### 22 — установка шкалы доступных групп (§8.7.2.18, 5.3.173)
    ИС: 40-37 — шкала групп
    РМР: 48-25 — шифр бюджета

### 23 — уничтожение бюджета (§8.7.2.19, 5.3.174)
    РМР: 48-25 — шифр бюджета

### 24 — запрос сведений о бюджете (§8.7.2.20, 5.3.175)
    ИС: 39-25 — длина буфера; 15-1 — число пропускаемых слов ответа

    ⚠ там же указано «РМР: 15-1 — адрес буфера» — одновременно с шифром
    в 24-разрядный РМР не помещается; сверить с komar.be/ra.be.

        В+1 — шифр администратора; В+2…В+4 — ресурсы по видам
        (48-25 — использованный, 24-1 — оставшийся);
        В+5… — подбюджеты; конец — слово из всех единиц.
    Реальная константа ОС: perekh.be:1729

### 25 — уничтожение области администратором (§8.7.2.21, 5.3.176)
    Формат аналогичен 02; только в режиме администратора.

### 27 — смена шифра (§8.7.2.23, 5.3.178)
    РМР: 48-25 — шифр. Только в режиме администратора.

### 30 — захват области (§8.7.2.24, 5.3.179)
    ИС: 42-37 — вирт.номер; 24 — 1 = монопольный захват;
        23 — 1 = безусловный (0 = условный, код ответа при занятости);

### 31 — освобождение области (§8.7.2.25, 5.3.180)

## 5. ВРЕМЕННЫЕ ФУНКЦИИ (АИСП < 10₈, без информационных слов)
=====================================================================

Выдаются как `Э63 <код>` с малым исполнительным адресом; путь —
РЕСУРС (не требуют 'КЛЮЧАР'). Состояние хранится в слове 39 ИПЗ
(perekh.be:95-117); при истечении — авост «ИСТЕКЛО ВРЕМЯ ПО ЭК».

| АИСП | Функция (§ руководства)                | Вход/выход          |
|------|----------------------------------------|---------------------|
| 0    | запрос времени до конца решения (5.3.181) | выход: СМ — время |
| 1    | печать времени решения на АЦПУ (5.3.182)  | —                  |
| 2    | отмена ограничения времени (5.3.184)      | СМ = текст «777777» |
| 3    | ограничение времени решения (5.3.183)     | СМ = текст «ЧЧММСС» |
| 4    | запрос времени ЦП (5.3.186)               | выход: СМ — время  |

Пример из ОС (perekh.be:702): `Э63 ’4’` — запрос времени ЦП.

Кодировка букв (полная цепочка, алфавит без Ё и Ъ):
А=040 Б=041 В=042 Г=043 Д=044 Е=045 Ж=046 З=047 И=050 Й=051
К=052 Л=053 М=054 Н=055 О=056 П=057 Р=060 С=061 Т=062 У=063
Ф=064 Х=065 Ц=066 Ч=067 Ш=070 Щ=071 Ы=072 Ь=073 Э=074 Ю=075 Я=076.
Измерены по листингу 14 букв (П,Р,И,В,Е,Т,К,Э,О,А,Д,Б,М,Ш) — все
совпадают; остальные — по правилу «037₈ + позиция без Ё и Ъ».
Для 'КЛЮЧАР': К=052 Л=053 Ю=075 Ч=067 А=040 Р=060.

'КЛЮЧАР' = 052 053 075 067 040 060₈ = в'1242547515620060'.

⚠ Латинские буквы (R, F в реальном имени «АRFА.ПЕРЕХВАТ») по
имеющимся листингам не выводились — получить из сборки пробы или из
таблицы УПП→Unicode в эмуляторе.

Правило записи п'…' в БЕМШ: строка из 6 букв — текст УПП (8 разрядов
на символ); строка только из восьмеричных цифр — ЧИСЛО
(п'000007' = 7, п'777777' = маска шести разрядов; disp70.be:423,
nombob.be:434).
